# RAG 调参笔记

> M5 混合检索落地过程中的参数决策与实测记录。后续检索质量迭代（M6 验收、评测集）在此追加。

## 1. 混合检索 SQL（internal/repo/search.go）

### 向量侧：余弦距离阈值 `embedding <=> vec < 0.85`

**发现**：HNSW 检索是 top-N 语义——`ORDER BY embedding <=> $2 LIMIT 50` 在任何查询下都会返回表内最近邻，即使最近邻与查询毫不相关（余弦距离 ≈ 1）。无阈值时"无命中空态"永远不会出现，前端无法展示"换个说法"空态（FR-10 例外）。

**决策**：余弦距离 > 0.85（即余弦相似度 < 0.15）的向量命中直接丢弃。集成测试用正交向量（相似度 0）验证空态通过。

**风险**：0.85 是保守起点。若评测集出现"相关但 embedding 不自信"的漏召回，放宽到 0.9；若出现明显不相关的向量噪声，收紧到 0.8。

### 关键词侧：`similarity(content, q) > 0.05` 而非 `%` 运算符（默认阈值 0.3）

**发现**：pg_trgm 的 `%` 相似度运算符默认阈值 0.3，对**中文短查询（2 字词）几乎永不命中**——实测 `similarity("限流中间件实现，使用固定窗口算法", "限流")` 约 0.06~0.12 量级（中文单字为独立字符，trigram 组合有限）。

**决策**：显式 `similarity > 0.05` 低阈值进 CTE，rank 仍按 similarity 排序。副作用：低阈值下 trigram 兜底会引入一些弱相关候选，但 RRF 融合时 rank 靠后（1/(60+50) ≈ 0.009），对最终排序影响很小；且 rerank 精排会进一步过滤。

**替代方案（未采用）**：`SET pg_trgm.similarity_threshold = 0.05` 会话级设置——影响同会话其他查询，且 GORM 连接池下会话管理复杂，不如显式写进 SQL 直观。

### RRF 融合：k=60，候选 Top-50

- 双侧各取 Top-50 候选，`score = Σ 1/(60 + rank)`；双命中（向量近且关键词近）天然排前。
- 50 条候选送 rerank（bge-reranker 类模型输入上限内）；检索页全量分页展示，问答引用取 Top-5（PRD R5）。

## 2. rerank 精排（internal/service/search.go）

- **降级策略**：未配置默认 rerank 条目（MODEL_001）或 rerank 调用失败时，**静默降级为 RRF 排序**——检索页可用性优先，模型配置不阻断检索。
- score 字段对外始终展示 RRF 融合分（API 设计 §5 示例 0.0317 为 1/(60+1)+1/(60+1) 量级），rerank 只影响排序不回显分数。
- **rerank 阈值（未启用）**：bge-reranker 的 relevance_score 低分截断（如 < 0.3 丢弃）暂未启用——候选已过向量/关键词双阈值，rerank 排序价值大于截断价值。评测集建立后视 precision 需要启用。

## 3. 切块参数（M4 遗留，影响检索粒度）

| 参数 | 当前值 | 说明 |
|---|---|---|
| maxChunkRunes | 800 rune | 单块上限；中文约 800 token 量级，bge-m3 8192 上限内 |
| overlapRunes | 100 | 递归字符切块重叠窗口 |
| minChunkRunes | 80 | 通用文本碎块并入阈值（MD 标题/代码块不合并，保留结构语义） |
| heading 前缀 | 块内容前拼标题路径 | 提升"块脱离上下文后仍可被语义命中"的概率 |
