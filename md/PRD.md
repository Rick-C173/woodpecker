# Woodpecker（啄木鸟）— AI 代码/技术文档知识库 产品需求文档

> 版本：v0.1 草案 · 日期：2026-11-22
> 技术实现基线见 [技术选型.md](./技术选型.md)，本文只描述产品行为。

## 1. 背景与目标

团队的代码与技术文档分散在 Git 仓库、Markdown 文件和各类网页中。开发者（尤其是新成员）在排查问题、了解设计原因、查找接口用法时，需要在多个仓库和文档间反复翻找，成本高且容易遗漏；通用 AI 工具无法回答涉及内部实现的问题。

Woodpecker 的产品决策：让团队把私有代码与文档接入一个自建知识库，用户用自然语言提问，系统基于知识库内容生成回答，并保证**每个回答都可溯源到原始出处**。

可观察的目标：用户提出一个关于内部代码或文档的问题后，能获得一条流式输出的回答，回答中每条引用可点击跳转到源文件的具体位置；当知识库中没有足够依据时，系统能明确说明"依据不足"而不是编造。

## 2. 用户与典型问题

主要用户：公司内部开发相关人员（开发、测试、运维等，几十人量级），支持同时接入多个代码仓库。权限采用**全局两级 + 知识库成员制**：管理员（建库、删库、授权、用户管理、模型配置、审计查看）与普通用户（仅在被授权的知识库内操作，按授权获得库内**管理者/编辑者/成员**三种角色之一）。角色矩阵见共享规则 R6。

| 问题类型 | 示例 |
|---|---|
| 接口/函数用法 | "用户登录接口怎么调用？参数有哪些？" |
| 设计原因 | "为什么订单模块用消息队列而不是同步调用？" |
| 报错排查 | "报错 XX 是哪里抛出的？通常什么原因？" |
| 功能定位 | "下载限流的实现在哪个文件？" |
| 文档查阅 | "部署文档里对内存配置的要求是什么？" |

## 3. 范围

**P0（本期）**

- 账密登录（管理员/普通用户两级，首登强制改密）
- 用户与权限管理：管理员建库、知识库成员授权（管理者/编辑者/成员）、用户管理（FR-13）
- 模型服务配置（管理员后台，存数据库，多供应商可切换）
- 知识库管理（操作权限按 R6 角色矩阵）
- 接入知识源：Git 仓库、文件上传（Markdown/代码/纯文本）、网页 URL；Git 手动同步；敏感文件自动排除
- 自动摄取管道，状态可见，失败可重试
- 对话问答：流式回答 + 引用溯源 + 会话历史；点踩反馈（FR-14）
- 检索页：不生成答案、纯内容搜索
- 操作审计查看（管理员，FR-15）

**P1（后续）**

- PDF / Office 文档接入
- MCP Server 能力（供 IDE Agent 查询知识库）
- Git 仓库定时自动同步
- 反馈统计与点赞、查询改写、RAG 评测集
- 知识库级自定义提示词、用户组批量授权、个人 API Token
- 公司 SSO（OIDC）对接、中文全文检索优化

**排除**：多租户、计费配额、消息通知、移动端。

## 4. 对象模型与状态

### 4.1 对象

| 对象 | 说明 |
|---|---|
| 知识库（Knowledge Base） | 内容的组织单元，对话与检索都发生在某个知识库内 |
| 文档（Document） | 知识库内的一条内容来源：一个 Git 仓库、一份上传文件或一个网页 |
| 分块（Chunk） | 文档切分后的最小检索单元；对话引用以分块为单位定位出处，但对用户不可直接管理 |
| 用户（User） | 系统账号；全局分管理员/普通用户，对知识库的访问由成员授权决定 |
| 会话（Conversation） | 一次连续的多轮问答 |
| 消息（Message） | 会话中的一条提问或回答 |
| 反馈（Feedback） | 用户对单条回答的点踩记录（含原因），见 FR-14 |
| 模型服务配置（Model Config） | 管理员维护的 LLM 供应商与模型条目（对话/向量/重排三类用途），见 FR-12 |

### 4.2 文档状态机（全文档唯一标准）

| 状态 | 含义 | 允许的操作 |
|---|---|---|
| 待处理 | 已登记，尚未开始摄取 | 删除 |
| 处理中 | 解析/切块/向量化进行中 | 删除（中止任务） |
| 已就绪 | 内容已入库，可被问答与检索引用 | 删除、重建索引 |
| 失败 | 摄取出错，错误原因可见 | 重试、删除 |

禁止的状态跳转：`失败 → 处理中`（必须经"重试"产生新任务）；`已就绪 → 待处理`（重建索引走"处理中"）。

## 5. 功能需求

### FR-01 登录与账号

**目的**：系统不对匿名用户开放；权限采用全局两级 + 知识库成员制（角色矩阵见 R6）。

- 首次部署初始化：第一个注册的用户自动成为管理员；此后自助注册默认关闭，账号由管理员创建（用户名 + 初始密码）。[Assumption, TBD] 可在系统设置中临时开启自助注册。
- 管理员创建的账号**首次登录强制修改初始密码**。
- 未登录访问任何页面重定向到登录页；支持退出登录；被禁用账号登录被拒绝并提示联系管理员。
- 密码规则：≥ 8 位；用户名全局唯一。
- 例外：用户名已存在、密码过短给出明确提示；密码错误超过 5 次，锁定 10 分钟。[Assumption, TBD]

### FR-02 知识库管理

**目的**：按项目或主题组织内容；权限粒度以知识库为单位（见 R6）。

- 创建：仅管理员（名称必填，≤ 50 字符；描述可选）。编辑：仅管理员，可修改名称与描述。
- 列表页：普通用户仅看到被授权的知识库，展示名称、描述、文档数、最近更新时间、自己在该库的角色（管理者/编辑者/成员）。
- 删除：仅管理员；需二次确认（输入知识库名称确认）；级联删除（文档、分块、会话一并清除），且不可恢复。
- 成员管理：管理员在知识库详情页维护成员（添加用户、指派/收回**管理者或编辑者**、移除成员）。
- 例外：名称重复仅提示不阻止；删除失败提示并提供重试；移除成员不影响其历史会话数据（会话随库保留，仅失去访问权）。

### FR-03 知识源接入 — Git 仓库

**目的**：以整个代码仓库为内容来源。

- 触发：具有接入权限的用户（管理者、编辑者或管理员，见 R6）在知识库详情页点击"接入 Git 仓库"，填写仓库地址；私有仓库需提供凭证（Token 或 SSH）。**同一个知识库可接入多个仓库**，每个仓库是一条独立文档。
- 处理规则：
  - 克隆默认分支；文件按扩展名分流：支持格式内的文件逐个摄取，其余忽略。
  - 自动跳过：二进制文件、依赖目录（如 node_modules、vendor）、.git 目录、超过单文件大小上限的文件。
  - 敏感文件自动排除（R1b）：命中排除规则的文件不进入解析与向量化，文件清单中标记"已排除"。
  - 支持配置忽略路径（glob 规则，可选）。[Assumption, TBD] 默认提供常见忽略模板。
- 手动同步：文档列表与详情提供"同步"操作（编辑者及以上，见 R6）。同步为增量处理：比对远端最新提交，新增/修改文件重新摄取、已删除文件清除其分块；期间问答使用旧内容不受影响。同步动作记入审计。
- 结果：创建一条"文档"，状态按 §4.2 走完整流程；就绪后文档详情可浏览已收录文件清单（含排除标记）。
- 例外：地址无法访问、凭证无效 → 直接置为失败并在文档详情展示原因；仓库过大（超限，见共享规则）→ 拒绝接入并提示；同步时远端不可达 → 旧内容保持可用并提示同步失败，可重试。

### FR-04 知识源接入 — 文件上传

**目的**：手工补充散落的文档与代码。

- 触发：具有接入权限的用户（编辑者及以上，R6）在知识库详情页"上传文件"，支持多选与拖拽。
- 支持格式：见共享规则"支持格式清单"；不支持的格式在上传时即被拒绝并说明。
- 处理规则：每个文件成为一条独立文档，进入 §4.2 状态机；同名文件允许重复上传（各自独立，不覆盖）。[Assumption, TBD]
- 例外：超过数量/大小上限的文件拒收并逐个提示；中断的上传不产生残留文档。

### FR-05 知识源接入 — 网页 URL

**目的**：收录在线文档页面。

- 触发：具有接入权限的用户（编辑者及以上，R6）在知识库详情页"接入网页"，填写 URL。
- 处理规则：[Assumption, TBD] MVP 抓取单个页面正文（去导航/页眉页脚）；整站爬取放 P1。
- 例外：URL 无法访问、非 HTML 内容 → 置为失败并展示原因；重试遵循共享规则。

### FR-06 摄取管道与任务进度

**目的**：让用户始终知道内容处于什么阶段、出了什么问题。

- 知识库详情页与文档列表实时展示每个文档的状态（§4.2）。
- 处理中的文档展示当前阶段（解析 / 切块 / 向量化）。
- 失败的文档展示失败原因摘要与"重试"按钮。
- 失败自动重试 ≤ 3 次（间隔递增），仍失败才置为失败状态并停止。[Assumption, TBD]
- 例外：用户删除"处理中"文档时，中止其未完成任务；系统重启后，中断任务按失败处理，可手动重试。

### FR-07 对话问答

**目的**：核心功能——基于知识库内容回答问题。

- 触发：在知识库内发起会话提问。
- 处理规则：
  - 提问前校验成员资格（R6）：无权限时返回"知识库不存在或无权访问"，不泄露库名。
  - 回答由管理员配置的默认对话模型生成（见 FR-12）；回答流式输出，逐字可见，可随时停止生成（已生成部分保留）。
  - 回答基于知识库内容生成；回答末尾附引用列表（见 FR-08）。
  - 支持多轮：后续提问可理解上文（"它支持哪些参数？"中的"它"）。
  - 回答中的代码块正常渲染，带语言高亮。
- 依据不足规则：当检索结果与问题相关度不足时，回答明确说明"知识库中未找到足够依据"，不得编造引用；此时不产出引用列表。
- 例外：模型服务不可用 → 会话内展示错误并允许重新生成；重新生成替换当前回答（保留原提问）。

### FR-08 引用溯源

**目的**：让回答可信、可核查。

- 每条回答末尾列出引用条目：编号 [1][2]…、来源文档名、位置（文件路径 + 行号范围，或标题路径）。
- 点击引用展开片段原文预览；预览中提供"跳转"入口。
- Git 仓库类文档的跳转目标：仓库内文件对应路径与行号；网页类：原始 URL。
- 同一处内容被多个分块命中时合并为一条引用。
- 单条回答引用数量上限：5 条。[Assumption, TBD]

### FR-09 会话管理

- 会话列表按知识库组织，展示标题（取首条提问摘要）与最近时间。
- 回到历史会话可继续提问；历史消息完整保留。
- 删除会话：二次确认，仅删除会话本身，不影响文档。
- 重命名会话：可选手动修改标题。

### FR-10 检索页

**目的**：不生成答案，直接查看知识库命中的原始内容。

- 触发：知识库成员（R6）在知识库内输入关键词或一句话。
- 结果：分块片段列表，含所属文档、位置、命中摘要；按相关度排序。
- 与 FR-08 相同的片段预览与跳转能力。
- 例外：无命中时展示空态并建议换个说法。

### FR-11 文档管理

- 文档列表：名称、类型（仓库/文件/网页）、状态、收录时间、失败原因（如有）。操作权限分级（R6）：接入/上传/重试/同步对编辑者开放；删除/重建索引仅管理者；成员只读。
- 重建索引：对"已就绪"文档重新执行完整摄取，期间问答不受影响（旧内容可用，完成后替换）。
- 删除文档：二次确认；级联删除其分块与引用关系。
- 文档详情：已收录文件清单（仓库类）、内容预览、状态历史（失败原因）。

### FR-12 模型服务配置（管理员）

**目的**：大模型供应商与密钥不写死在配置文件，由管理员在后台配置，兼容任何 OpenAI 兼容服务。

- 仅管理员可见入口；普通用户不可见、不可调用。
- 管理内容两级：
  - **模型服务**：名称、Base URL、API Key（加密存储，页面不回显明文）、启用/停用。
  - **模型条目**：所属服务、用途（对话 / 向量化 / 重排）、模型名、参数（如 temperature）、默认标记。
- 每个用途必须有且仅有一个默认条目；对话、向量、重排三个默认可来自不同供应商（例如对话用 DeepSeek、向量用 SiliconFlow 的 BGE-M3、重排用另一个服务）。
- 保存时提供"测试连接"：逐项验证该服务下对话、向量、重排的可用性并展示结果。
- 生效规则：修改默认条目后，新请求立即使用新配置；进行中的请求用旧配置完成。已停用的服务不允许作为默认。
- 例外：删除默认条目前必须先切换默认到其他条目；API Key 无效在"测试连接"中报错，不阻断保存。
- 摄取管道使用向量与重排的默认配置；对话问答使用对话默认配置。

### FR-13 用户与权限管理（管理员）

**目的**：管理员集中管控账号与知识库访问，授权入口统一收口。

- 用户列表：用户名、状态（启用/禁用）、是否管理员、加入时间、可访问知识库数。
- 创建用户：用户名 + 初始密码（随机生成或指定），首次登录强制修改。
- 禁用/启用：禁用立即生效——终止其进行中的回答流与登录状态；数据与历史保留。
- 重置密码：生成新的初始密码，该用户下次登录强制修改。
- 授权管理：为用户授予/移除知识库成员资格、指派/收回某库管理者或编辑者（与 FR-02 成员管理为同一能力的两个入口）。
- 例外：不能禁用自己；最后一个管理员不可被降级或禁用；被移除的成员其历史会话保留但失去访问（见 FR-02）。

### FR-14 回答反馈

**目的**：以最低成本建立 RAG 质量闭环，定位"引用不相关/内容错误"的坏案例。

- 触发：知识库成员在任意一条回答下点踩（点赞与统计 P1）。
- 点踩需选择原因（单选）：引用不相关 / 内容错误 / 没有找到想要的 / 其他（"其他"必填一句话说明）。可撤销。
- 反馈列表仅管理员可见（按原因/知识库/时间筛选），用于定位坏案例；反馈不改动回答本身。
- 例外：重复点踩覆盖前次；删除会话时其反馈一并删除。

### FR-15 操作审计查看（管理员）

**目的**：敏感操作可追溯。

- 记录范围：登录失败与锁定、权限变更（授权/移除/角色变更）、知识库创建与删除、文档删除、模型服务配置变更、Git 接入与同步、敏感文件排除规则变更。
- 审计页：按操作者、对象类型、时间范围筛选，倒序展示；每条含操作者、动作、对象、时间、结果。
- 审计记录不可编辑、不可删除；保留期限 ≥ 180 天。[Assumption, TBD]
- 例外：大时间范围分页展示；审计写入失败不影响业务主流程（记运行日志并告警）。

## 6. 共享规则（多模块引用，唯一定义）

**R1 支持格式清单**

| 知识源 | 支持内容 |
|---|---|
| 文件上传 | Markdown（.md/.markdown）、纯文本（.txt）、常见代码源文件（按扩展名识别，含 .go/.py/.java/.js/.ts/.sql/.yaml/.json 等） |
| Git 仓库 | 同上按扩展名分流 |
| 网页 | HTML 正文 |

不在清单内的格式：上传时拒绝；仓库/网页中出现时静默跳过。

**R1b 敏感文件排除清单**（Git 接入与上传共用）

默认排除、不进入解析与向量化：`.env*`、`*.pem`、`*.key`、`id_rsa*`、`credentials*`、`*secret*`、`*.p12`、`secrets/` 目录。命中文件在文件清单中标记"已排除"。排除清单可由管理员调整。[Assumption, TBD 清单细项]

**R2 限制与配额** [Assumption, TBD]

- 单个上传文件 ≤ 5 MB；单次上传 ≤ 50 个文件。
- 单个 Git 仓库 ≤ 1 GB / 5 万文件；超限拒绝接入。
- 每个知识库文档数 ≤ 1000。

**R3 失败与重试**

摄取失败自动重试 ≤ 3 次（间隔递增），仍失败置为"失败"并可手动重试；手动重试产生全新任务，不续用旧任务。

**R4 删除级联**

删除知识库 → 级联删除其全部文档、分块、会话；删除文档 → 级联删除其分块。所有删除均二次确认且不可恢复。

**R5 引用规则**

引用以分块为单位；编号按回答中出现顺序排列；无依据时不产出引用（见 FR-07 依据不足规则）。

**R6 权限矩阵（全文档唯一定义）**

| 操作 | 管理员 | 知识库管理者 | 编辑者 | 成员 |
|---|---|---|---|---|
| 创建 / 删除知识库 | ✓ | ✗ | ✗ | ✗ |
| 成员授权（添加、移除、指派角色） | ✓ | ✗ | ✗ | ✗ |
| 删除文档、重建索引 | ✓ | ✓ | ✗ | ✗ |
| 接入 / 上传知识源、重试、手动同步 | ✓ | ✓ | ✓ | ✗ |
| 问答、检索、查看引用、点踩反馈 | ✓ | ✓ | ✓ | ✓ |
| 用户管理、模型服务配置、审计查看 | ✓ | ✗ | ✗ | ✗ |

- 库内角色由管理员指派，层级为管理者 > 编辑者 > 成员；用户不可自建知识库或自封角色。
- 编辑者定位：可**补充**内容（接入/上传/同步/重试），不可**破坏**内容（删除/重建）——"新人可补充、不可删改"。
- **不可见原则**：非成员（且非管理员）对知识库完全不可见——列表不展示、检索不到、问答返回"不存在"，避免敏感仓库标题泄露。
- **失效时机**：移除成员 / 收回角色 / 禁用账号立即生效；进行中的回答读完即止，后续提问被拒。
- 管理员无需授权即可访问所有知识库；越权查看与操作均记审计（FR-15）。
